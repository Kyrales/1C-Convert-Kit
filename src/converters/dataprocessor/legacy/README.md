# Legacy CMD скрипты конвертации обработок и отчетов

## Статус: УСТАРЕЛО

Эти CMD скрипты больше **НЕ ИСПОЛЬЗУЮТСЯ** в текущей версии приложения.

## История

Ранее конвертация обработок и отчетов выполнялась через CMD скрипты:
- `dp2epf.cmd` - конвертация в EPF файл (внешняя обработка)
- `dp2erf.cmd` - конвертация в ERF файл (внешний отчет)
- `dp2xml.cmd` - конвертация в XML
- `dp2edt.cmd` - конвертация в EDT проект

## Текущая реализация

Вся функциональность перенесена в Python класс **DataProcessorConverter**:
- Расположение: `src/converters/dataprocessor/converter.py`
- Использует объектно-ориентированный подход
- Интегрирован с ConverterRegistry
- Поддерживает пакетную обработку множественных файлов
- Автоматически определяет тип (обработка/отчет)

## Использование

Для конвертации обработок и отчетов используйте:

```python
from converters.dataprocessor.converter import DataProcessorConverter

converter = DataProcessorConverter(env_vars)
converter.validate()
converter.convert()
converter.cleanup()
```

Или через CLI:
```bash
python src/core/convert.py --env projects/MyDataProcessor
```

## Особенности

DataProcessorConverter автоматически:
- Обрабатывает все файлы в директории `ExternalDataProcessors/` и `ExternalReports/`
- Определяет тип файла (обработка → .epf, отчет → .erf)
- Использует базовую конфигурацию если указана (V8_BASE_CONFIG)
- Создает временную информационную базу для конвертации

## Причины миграции

1. **Устранение дублирования кода** - общая логика вынесена в BaseConverter
2. **Пакетная обработка** - автоматическая обработка всех файлов в директории
3. **Лучшая тестируемость** - Python код легче тестировать
4. **Единообразная обработка ошибок** - централизованная обработка
5. **Гибкость** - легко добавлять новые форматы

## Сохранение

Эти файлы сохранены только для истории и справки. Они не участвуют в работе приложения.
